# 涛博士运动康复 · 静态交互设计原型

用于查看与讨论界面和工作流程。使用麦岛店、崂山店的真实门店名称；客户、工作人员、预约、计划、收款和业绩均为虚构示例。

支持客户、康复师、老板、前台和店长角色体验；可模拟到店、服务照片留底、消课、收款、退款记录、平台待结算与到账。本页面不会执行真实付款或退款。

页面数据仅保存在当前访客页面内存中，刷新恢复初始示例。新录入的操作时间采用页面显示的示例日期和当前上海时钟，便于在同一个示例营业日试用；正式系统由服务器记录真实时间。未接入微信登录、真实客户档案、持久数据库或平台自动对账。

手动收款与套餐核对：前台或老板填写实际到账金额、门店、客户和付款方式；套餐／续费款可选择同客户、同办卡门店的套餐，成交金额与总次数分别显示。办理或续接套餐成功后可直接进入该套餐收款登记；已登记过的款项由老板打开原收款关联，避免重复录入。尚未办卡的款项可先记收款；单次服务和其他用途不关联套餐。平台待结算单不计实收，到账子单继承原套餐关联且只计一次。收款不改变次数或消费业绩，旧档案迁入不自动补记历史收入。“套餐与收款差额”仅供核对，不能直接当作客户欠款；客户端继续不显示金额。

退款后的套餐处理：只允许老板登记实际已经退回的钱。关联套餐的退款必须明确选择保留现有次数或结束该套餐，并填写原因；结束后可用次数为零，原总次数、真实使用、服务记录和消费业绩保留，不把未用次数当成已消课。结束套餐不能继续消课、激活或作为耗尽套餐续接；需另办新套餐。撤销错误退款只恢复该退款造成的结束状态，其他有效结束决定仍保留；错误服务另由老板按原流程撤销，不随退款自动改动业绩。

每日营业对账：老板、前台、店长首页增加“今日对账”。前台或老板按营业日填写微信、支付宝、现金、银行转账的实际收款减退款，可填写退款日的负数；平台未到账不参与对账。四项分别无差额后，老板确认，前台不能自己确认。提交和确认不登记新收入或执行转账；重新提交保留此前版本。当天收款、退款、结算或更正发生变化后，显示“账目已变化，需重新核对”，旧确认保留留底。权限与导出按实际门店限制，并去除内部提交标识与账目指纹。这三项为本次原型补强，正式身份认证、数据库保存、自动账单同步和备份恢复仍须后续接入。

老板快捷入口：`?preview=boss`；前台快捷入口：`?preview=frontdesk`。这些仅选择演示角色，正式系统必须使用真实身份和服务端权限。

客户分享入口：`?preview=customer`。直接展示客户页面，隐藏角色切换与管理演示控件，保留计划、次数、预约、服务记录及评价体验，并持续标注示例资料。原链接及老板、前台入口继续可用。此入口是展示模式，不代表正式账号权限。

新增客户评估与前台工作考核：前台在授权门店代录评估项目、指标和说明，由指定评估康复师、客户负责人或老板确认后供客户查看；历史记录及有原因的撤销保留。评估记录独立于消课、收款和康复计划。实际评估时间按上海时区校验，尚未发生的时间不能登记或确认。老板可从前台人员的“工作记录”查看经办数据并填写考核结论、改进事项和日期，前台只查看自己的考核。所有记录仍仅保存在当前页面内存中。

客户服务评价：除客户本人外，评分、文字反馈与回访处理记录仅老板可查看；康复师和前台的界面、服务明细、工作待办及演示导出不显示这些记录。客户填写前和查看已提交评价时均展示权限提示，申请联系交由老板处理。此处仅演示角色规则，正式版仍须以服务器鉴权和隔离的数据响应实现相同权限。

同行预约：前台、老板或有客户权限的康复师可一次安排2至20位已建档客户，在同一门店、同一日期整点或半点到店，每人各自选择不同且有资格服务该客户的康复师。整组统一校验，任一成员冲突或越权均不保存，相同请求重试只返回原组。每人一条独立预约（仅共用groupId，不携带其他人的档案），分别到店、改约、取消、消课与评价；预约不改变套餐次数或收款。朋友未建档时先由老板、前台或康复师按建档权限建立基本档案，再由有预约权限的工作人员安排同行预约。

店长入口：`?preview=manager`（麦岛店）或 `?preview=manager&store=b`（崂山店）。店长账号绑定一家门店，首页查看本店今日实收、预约、完成服务及待处理事项，并可查看本店客户、服务照片留底、评估、收退款与平台结算、人员业绩和前台考核。所有明细和导出按记录实际门店过滤；同一客户的两店套餐分别使用，店长查看本店套餐次数，其他门店的工作记录不展示。无明确门店的历史待办归客户所属门店。客户私人评价及评价回访任务继续仅客户本人和老板可见，不给店长开放。店长可为已有本店档案的客户新建本店单人或一次约多天的预约、确认本店待预约申请；创建与确认均检查实际绑定门店、客户权限、已确认排班和60分钟冲突，并保留真实店长身份。店长不编辑已有预约、不取消、不安排同行整组，也不建档、录入服务前表、收款、消课、改排班或确认日结。其他录入由对应工作人员办理，退款、更正、人员和权限调整由老板处理。老板在“人员管理”新增、编辑或停用店长；新门店可绑定新的店长。以上仅演示权限，正式上线须由服务端验证真实账号。

客户预约首页：预约为主要入口，三步选择门店、期望日期时间、核对并提交申请。时间以半小时选择，不代表实时空位。客户看本店剩余次数，不展示金额或充值余额。评分不预选，除本人外仅老板可见。

流程完善（2026-10-09）：前台从预约点击“记收款”会自动带入客户、门店和预约，仍须核对实际到账金额与用途；不会要求套餐客户重复付费。康复师登记时明确选择“套餐消课”或“单次服务”，后者关联同一客户、同店的有效单次到账款，不扣套餐次数，实际服务完成后按关联金额生成消费业绩。一笔单次款只能支持一条有效服务；撤销只冲回业绩，实际退款另由老板录入。客户同时持有两店套餐时首页并列提示各店余次，仍不显示金额。

老板可在客户档案“指定各店执行师”，保留统一负责人和各店独立套餐，解决外店首次预约没有可选人员的问题。只有指定门店的执行权限不会扩大为所有门店操作权限。预约申请可以确认、无法安排、建议替代时间或关闭过期申请；替代安排须客户接受后再由门店确认。客户取消已确认预约须门店处理后才释放时段，改约后原取消申请失效并留底；相同时间改约会提示无变化。错误服务撤销后如原预约与其他安排冲突，显示待重新安排，金额与次数更正照常完成。

接待表专业复核时明确下一步负责人和计划日期，生成门店待办；一般待办需填写实际结果才能完成。老板可调整负责人和期限，接待表显示当前安排，复核时旧安排保留作为历史。服务小结可填写下次建议，由客户负责人或老板确认后更新客户下一步。前台首页优先显示今天接待与预约，日结对账折叠；老板先看实际收入、服务消费业绩、完成服务和待处理工作。

预约申请单独留存；申请不扣次、不记收款。本店店长、授权门店前台、客户负责人或老板核对排班后，调用同一预约流程确认，重新检查权限与既有60分钟预约冲突。申请去重及提交标识别名防止重复申请；失败保留填写内容。已处理的申请展示提交时历史，当前安排以真实预约记录为准。已接入页面内已确认排班校验：未排班、休息、非排班门店和完整60分钟超出上下班时间均不能安排；正式系统的排班同步和通知发送仍待服务端接入。

本店套餐：同一客户可以持有麦岛店和崂山店两份套餐，各自保留成交金额、总次数、期初使用及消课。套餐只能在所属店使用；消课明确选择本店有余套餐，撤销恢复原套餐槽位。老板可办理新本店套餐，不自动生成收款或消费业绩。新纸质档案和续费绑定门店。纯模型保留未绑定旧套餐的兼容路径，须核对所属店后用于实际迁移，不能据此将新卡当作两店通用。

前台新客户接待：首页“接待新客户”、客户列表保留同一入口。先按手机号检查原档案，再记录姓名、年龄、客户自述主要问题、接待门店及本店负责康复师。外店已有档案只提示请老板核对权限，不暴露无权限身份；同一手机号禁止重复建档，连续提交幂等。建档后显示明确结果并可直接为这位客户预约；老客户可按姓名/手机号查找、查看基本接待资料。新档案未办套餐、不收款、不消课、不产生评估结论或业绩；老板后续办理首张本店套餐。前台只在授权且启用的门店建档，不修改原档案负责人，不办卡、改次数或处理退款。全部仍是虚构页面内存演示，真实资料需正式服务端接入。


工作角色建档：前台在授权营业门店录入新客户，老板可选全部营业门店。康复师当前保留本人门店、本人负责的建档路径，服务记录是否统一由前台代录待业务确认。店长以本店监管查看为主，仅例外开放本店新建单人或一次约多天的预约和确认待预约；没有建档、填表、改排班、排班审批或日结确认权限，页面和业务接口同时拒绝其他写入。本次权限要求优先于早期原型约定。基础档案保存年龄和客户自述问题，不产生费用、套餐、服务或业绩。

纸质流程数字化：前台 → 评估 → 初访与评估 → 填写本次接待表。姓名、电话和负责人从客户档案带入；问题、年龄、目标在表内填写，部位、持续时间、活动影响、客户自述疼痛和背景信息按需记录。十项服务前问题逐项选“是／否／不清楚”，默认不选；全部填否仍待负责人复核，未成年须补充监护人。保存后由当前在职负责康复师或老板复核并记录具体下一步，保存实际复核岗位、人员和交办待办；老板不能替客户填写评分。旧回答、录入人和日期保留；下一次情况改变可以新增记录，历史不能替代本次确认。老板／店长工作台集中显示本权限范围的待复核数量、主要问题、需要核对事项、负责人和下一步，完整详情按需打开。专业评估、出席、套餐和收款沿用原有模块，接待表不会重复登记或自动扣次。客户端及客户导出不显示内部接待表。预览均为虚构，真实健康资料不能录入公开演示。


康复师排班：老板、店长、前台和康复师工作端增加“排班”入口，按日期显示09:00–19:00、休息或未排班。预览默认展示今日起14天虚构班次（许映今日休息），其他日期须先由老板确认；加载真实状态不自动补排班。前台在授权门店只提交调整申请，原排班保持不变。老板批准或直接保存后生效，店长仅查看班次和申请处理进度。调整须填写原因，支持整点及半点，历史只读，版本变化要求重新核对。会影响现有预约时必须先处理预约，不能直接改成休息或缩短到无法完成服务。

每次生效变更原子生成老板系统内通知，保存修改人／申请人、批准人、门店、康复师、日期、改前改后、原因和生效时间；标为已读后仍留底。微信通知意向保留为 pending_integration，预览明确“待正式接入，当前未发送”，不会调用微信或发送真实消息。前台无直接改排班权限，店长只读本店，康复师只读本人，客户不显示内部排班表或通知。导出沿用同样权限，过滤内部提交标识。

单人预约、同行预约、客户申请和改约均核对已确认班次。开始时间列表只显示可预约时段，班外、休息、未排班及已有预约占用的时段直接移除；每次服务按60分钟预留，10:00已有预约时，同一康复师的09:30、10:00、10:30均不显示，09:00与11:00可继续安排。修改日期、门店、康复师或同行人员后重新计算完整时间列表，取消预约后释放时段；原选择失效时清空并提示重新选择，不自动换到其他时间。改约排除本人正在修改的原预约，同行预约显示全部参与客户与康复师共同可用的时间。客户端可选择该店有客户服务权限的康复师。确认申请时再次检查排班与时间冲突；申请不占用时段、不收款、不扣次数。服务更正仍恢复原套餐次数和业绩，如果原预约已不符合当前排班，则保留为“待重新安排”，不会阻止合法更正或自动取消客户预约。


老板人员管理：老板端 → 人员管理，可新增和编辑康复师、前台、店长的姓名、手机号（可稍后补充）、门店及备注。前台可授权多家营业门店，店长和康复师分别绑定一家门店；岗位权限固定显示，不需要逐项配置。只有真实演示老板 boss:boss 可写，其他岗位无法通过表单或模型修改人员。手机号为联系资料，不代表开通微信登录；非空须为有效且不重复的人员手机号。本版本每个岗位按独立人员录入，兼岗安排待正式账号设计。

编辑可停用或恢复人员，保留同一人员ID和历史服务、业绩、收款及门店归属。改动保存原因、改前改后、版本，重复提交只更新一次；资料版本已变更则提示重新核对，重开不恢复陈旧版本草稿。前台和店长的门店范围即时生效，停用人员不再出现在身份切换菜单。康复师停用前须转交负责客户、处理待办及本人/协作未完成预约；换所属门店还须核对处理今日和未来工作排班，系统不会自动迁移班次。新康复师需要老板设置排班后才能预约。

页面刷新会清除本次新增/修改并恢复虚构示例，所有人员演示均不创建真实账号。正式上线需要老板认证、服务端岗位和门店鉴权、数据库、操作留痕与安全的数据响应；请勿在公开预览录入真实人员或客户隐私。老板演示导出保留人员修改记录但过滤内部提交标识和重放校验载荷。

康复师预约查看：康复师端 → 客户 → 查看预约，也可从工作台点击预约详情。展示本人负责或参与有效服务的客户申请及已安排预约，保留时间、门店、项目、主康复师、协作人员、状态与改约说明。申请为提交时的快照，已处理申请可打开最新预约记录。其他康复师及停用人员不能查看，唯一服务撤销后参与者失去该客户权限；协作参与者的申请确认、取消权限不扩大，客户私人评分仍只给客户本人和老板。全部为页面内虚构演示，正式系统须由服务器对真实账号实行相同权限。


每日员工工作：老板按门店和日期查看实际已完成的主服务、协作以及前台到店接待；店长仅看本店。康复师明细默认折叠，前台接待与新建档分别显示。同一客户、同一门店、同一上海营业日按首次实际到店去重；跨店、跨日用人次，老板代登记或归属不明的到店单列，不猜测前台。新建档不等于到店，纸质旧档迁入不计新建档考核；退款、未结算、撤销服务按原现金/履约口径各自处理。统计只依据现有登记，未登记的咨询来访尚不计入。10%业务、30%康复师、60%门店留存的比例已提出，提成基数、业务归属与前台服务代录范围待用户确认后实现，本版本不计算或发放提成。

# 涛博士运动康复 · 静态交互设计原型

用于查看与讨论界面和工作流程。当前资源版本为 `20261011-therapist-phone-package-owner-6`。门店为麦岛店、崂山店及待配置的苏州店；客户、预约、计划、收款和业绩仍为虚构示例。苏州尚无地址、员工和排班，显示“地址待配置”，未配置人员和已确认班次不能预约，不生成虚构员工、客户或营业日结待办。

支持客户、康复师、老板、前台和店长角色体验；可模拟到店、服务照片留底、消课、收款、退款记录、平台待结算与到账。本页面不会执行真实付款或退款。

页面数据仅保存在当前访客页面内存中，刷新恢复初始示例。新录入的操作时间采用页面显示的示例日期和当前上海时钟，便于在同一个示例营业日试用；正式系统由服务器记录真实时间。未接入微信登录、真实客户档案、持久数据库或平台自动对账。

手动收款与套餐核对：前台或老板填写实际到账金额、门店、客户和付款方式；套餐／续费款可选择同客户、同办卡门店的套餐，成交金额与总次数分别显示。办理或续接套餐成功后可直接进入该套餐收款登记；已登记过的款项由老板打开原收款关联，避免重复录入。尚未办卡的款项可先记收款；单次服务和其他用途不关联套餐。平台待结算单不计实收，到账子单继承原套餐关联且只计一次。收款不改变次数或消费业绩，旧档案迁入不自动补记历史收入。“套餐与收款差额”仅供核对，不能直接当作客户欠款；客户端继续不显示金额。

退款后的套餐处理：只允许老板登记实际已经退回的钱。关联套餐的退款必须明确选择保留现有次数或结束该套餐，并填写原因；结束后可用次数为零，原总次数、真实使用、服务记录和消费业绩保留，不把未用次数当成已消课。结束套餐不能继续消课、激活或作为耗尽套餐续接；需另办新套餐。撤销错误退款只恢复该退款造成的结束状态，其他有效结束决定仍保留；错误服务另由老板按原流程撤销，不随退款自动改动业绩。

每日营业对账：老板、前台、店长首页增加“今日对账”。前台首次或老板按营业日填写微信、支付宝、现金、银行转账的实际收款减退款，可填写退款日的负数；平台未到账不参与对账。四项分别无差额后，老板确认，前台不能自己确认。提交和确认不登记新收入或执行转账；已保存版本仅老板可以重填，保留此前版本。当天收款、退款、结算或更正发生变化后，显示“账目已变化，需重新核对”，旧确认保留留底。权限与导出按实际门店限制，并去除内部提交标识与账目指纹。这三项为本次原型补强，正式身份认证、数据库保存、自动账单同步和备份恢复仍须后续接入。

老板快捷入口：`?preview=boss`；前台快捷入口：`?preview=frontdesk`。这些仅选择演示角色，正式系统必须使用真实身份和服务端权限。

客户分享入口：`?preview=customer`。直接展示客户页面，隐藏角色切换与管理演示控件，保留计划、次数、预约、服务记录及评价体验，并持续标注示例资料。原链接及老板、前台入口继续可用。此入口是展示模式，不代表正式账号权限。

客户评估与前台工作考核：前台可在授权门店代录实际评估，由本次选定评估师本人核对确认后供客户查看；老板可以监督确认，其他评估师不能代确认。员工保留本人评估登记、初访复核与确认发布流程。评估独立于消课、收款和计划，实际时间不得尚未发生。老板可查看前台经办记录并新增考核结论；前台只看本人考核。错误记录由老板有原因撤销，历史原文、作者、确认人与日期保留，不允许通过新建入口带已有ID改老记录。

客户服务评价：除客户本人外，评分、文字反馈与回访处理记录仅老板可查看；康复师和前台的界面、服务明细、工作待办及演示导出不显示这些记录。客户填写前和查看已提交评价时均展示权限提示，申请联系交由老板处理。此处仅演示角色规则，正式版仍须以服务器鉴权和隔离的数据响应实现相同权限。

同行预约：前台、老板或有客户权限的康复师可一次安排2至20位已建档客户，在同一门店、同一日期整点或半点到店，每人各自选择不同且有资格服务该客户的康复师。整组统一校验，任一成员冲突或越权均不保存，相同请求重试只返回原组。每人一条独立预约（仅共用groupId，不携带其他人的档案），分别到店、改约、取消、消课与评价；预约不改变套餐次数或收款。朋友未建档时先由老板、前台或康复师按建档权限建立基本档案，再由有预约权限的工作人员安排同行预约。

店长入口：`?preview=manager`（麦岛陈康）或 `?preview=manager&store=b`（崂山何赞峰）。店长经营监管仅本店只读，客户私人评价不给店长。全部在职老板、前台、店长、治疗师可跨店查看预约必要基本信息、新建单人／多日预约、确认客户申请、确认今天实际到店，并从该预约填写本次初访表；不因此获得跨店经营、财务、照片或历史临床档案权限。店长可直接取消本店预约并审批本店前台取消，不能取消异店预约、编辑已有预约、收款、消课、改排班或确认日结。资料与权限由老板维护，店长仍不具新客户建档权限。

客户预约首页：预约为主要入口，三步选择门店、期望日期时间、核对并提交申请。时间以半小时选择，不代表实时空位。客户看本店剩余次数，不展示金额或充值余额。评分不预选，除本人外仅老板可见。

流程完善（2026-10-09）：前台从预约点击“记收款”会自动带入客户、门店和预约，仍须核对实际到账金额与用途；不会要求套餐客户重复付费。康复师登记时明确选择“套餐消课”或“单次服务”，后者关联同一客户、同店的有效单次到账款，不扣套餐次数，实际服务完成后按关联金额生成消费业绩。一笔单次款只能支持一条有效服务；撤销只冲回业绩，实际退款另由老板录入。客户同时持有两店套餐时首页并列提示各店余次，仍不显示金额。

老板可在客户档案“指定各店执行师”，保留统一负责人和各店独立套餐，解决外店首次预约没有可选人员的问题。只有指定门店的执行权限不会扩大为所有门店操作权限。预约申请可以确认、无法安排、建议替代时间或关闭过期申请；替代安排须客户接受后再由门店确认。客户取消已确认预约须门店处理后才释放时段，改约后原取消申请失效并留底；相同时间改约会提示无变化。错误服务撤销后如原预约与其他安排冲突，显示待重新安排，金额与次数更正照常完成。

接待表专业复核时明确下一步负责人和计划日期，生成门店待办；一般待办需填写实际结果才能完成。老板可调整负责人和期限，接待表显示当前安排，复核时旧安排保留作为历史。员工新服务小结可填写下次建议，由老板核对后修改客户已保存的下一步。前台首页优先显示今天接待与预约，日结对账折叠；老板先看实际收入、服务消费业绩、完成服务和待处理工作。

预约申请单独留存；申请不扣次、不记收款、不占时段。全部在职工作人员可核对并确认，确认时重新检查实际当前人员、门店、已确认排班及60分钟冲突。单次、同行和多日预约均每人每次分别选治疗师，不改统一负责人或老预约。既有预约的改约／重新安排仅老板修改；客户仍可提交改约意愿。提交失败保留填写内容；相同请求同内容重试不重复创建，内容变化不能复用标识。

本店套餐：客户可同时持有各店套餐，分别保留金额、总次数、期初使用与消课；只能在所属店使用。当前虚构历史示例保留麦岛与崂山两店套餐，不为苏州生成套餐或收款。老板可办理、续接本店套餐，不自动产生收入或业绩。员工按原权限登记实际服务，撤销由老板恢复原套餐槽位并保留原记录；纯模型旧未绑定套餐兼容只供核对旧档迁入，不是多店通卡。

前台新客户接待：首页“接待新客户”、客户列表保留同一入口。先按手机号检查原档案，再记录姓名、手机号、年龄、接待门店及本店所选评估师（默认王勤涛）；建档不选择治疗师，问题在本次初访表填写。外店已有档案只提示请老板核对权限，不暴露无权限身份；同一手机号禁止重复建档，连续提交幂等。建档后显示明确结果并可直接为这位客户预约；老客户可按姓名/手机号查找、查看基本接待资料。新档案未办套餐、不收款、不消课、不产生评估结论或业绩；老板后续办理首张本店套餐。前台只在授权且启用的门店建档，不修改原档案负责人，不办卡、改次数或处理退款。全部仍是虚构页面内存演示，真实资料需正式服务端接入。


工作角色建档：老板可为全部营业门店建档，前台仅授权门店，治疗师保留本人门店建档范围，店长没有建档权限。新档评估师默认王勤涛，按店选择本店实际评估名单；统一负责人留空，治疗师在每次预约分别选择。基础档案不产生服务、费用、套餐或业绩。康复师建档只记录姓名、年龄、门店与评估师，不录入客户手机号；号码留空待老板核对补充，任意非空手机号均拒绝，不提供号码查重。新建空号码的同请求安全重放；旧治疗师建档请求若携带号码仍拒绝，需由老板核对原档案，不能用旧请求查看号码。

纸质流程数字化：已确认预约 → 今天实际到店 → 填写本次初访与服务前表 → 本次所选评估师复核／本人专业评估 → 评估师本人确认后客户可见。全员仅从有效当日到店预约接待，姓名从基本档案带入，联系电话仅按原授权岗位可见，康复师端不显示；十项问题逐项填写，未成年补监护人。所选评估师、录入岗位、实际录入人、复核人、原因与时间留底。旧答案不能代替本次核对，情况变化新增记录，保存历史不能被新建接口覆盖。接待不扣次、不收款；历史详情仍按原角色和实际门店范围查看，客户不看内部接待表。


康复师排班：老板、店长、前台和治疗师均可查看各自授权排班。麦岛／崂山实际在职治疗师有当前示例日起14天虚构已确认班次，苏州没有班次；加载真实状态不自动补排班。前台在授权门店提交调整申请，老板审批或直接保存才生效；店长仅本店查看、治疗师只看本人。变更必须有原因与版本核对，影响既有预约时先处理预约。新康复师未排班不能约。历史示例人物与班次不冒充当前在职人员。

每次生效变更原子生成老板系统内通知，保存修改人／申请人、批准人、门店、康复师、日期、改前改后、原因和生效时间；标为已读后仍留底。微信通知意向保留为 pending_integration，预览明确“待正式接入，当前未发送”，不会调用微信或发送真实消息。前台无直接改排班权限，店长只读本店，康复师只读本人，客户不显示内部排班表或通知。导出沿用同样权限，过滤内部提交标识。

单人预约、同行预约、客户申请和改约均核对已确认班次。开始时间列表只显示可预约时段，班外、休息、未排班及已有预约占用的时段直接移除；每次服务按60分钟预留，10:00已有预约时，同一康复师的09:30、10:00、10:30均不显示，09:00与11:00可继续安排。修改日期、门店、康复师或同行人员后重新计算完整时间列表，取消预约后释放时段；原选择失效时清空并提示重新选择，不自动换到其他时间。改约排除本人正在修改的原预约，同行预约显示全部参与客户与康复师共同可用的时间。客户端可选择该店有客户服务权限的康复师。确认申请时再次检查排班与时间冲突；申请不占用时段、不收款、不扣次数。服务更正仍恢复原套餐次数和业绩，如果原预约已不符合当前排班，则保留为“待重新安排”，不会阻止合法更正或自动取消客户预约。


老板人员与门店管理：老板端 → 人员管理，可新增、编辑或停用治疗师、前台、店长；新增门店及编辑各门店名称、地址。编辑门店使用稳定ID、资料版本、必填原因、前后值和修改人／时间，原预约、服务、人员和客户归属不迁移；地址未知可留空。同一请求只保存一次，版本变化重开核对；修改名称不创造新门店。员工可以查看工作所需门店信息，无法打开管理编辑表或伪造修改请求。只有 boss:boss 能维护管理资料和修改已有预约、客户已存计划、收退款更正与旧业务记录；员工新录入及明确状态操作继续按原授权。

编辑可停用或恢复人员，保留同一人员ID和历史服务、业绩、收款及门店归属。改动保存原因、改前改后、版本，重复提交只更新一次；资料版本已变更则提示重新核对，重开不恢复陈旧版本草稿。前台和店长的门店范围即时生效，停用人员不再出现在身份切换菜单。康复师停用前须转交负责客户、处理待办及本人/协作未完成预约；换所属门店还须核对处理今日和未来工作排班，系统不会自动迁移班次。新康复师需要老板设置排班后才能预约。

页面刷新会清除本次新增/修改并恢复虚构示例，所有人员演示均不创建真实账号。正式上线需要老板认证、服务端岗位和门店鉴权、数据库、操作留痕与安全的数据响应；请勿在公开预览录入真实人员或客户隐私。老板演示导出保留人员修改记录但过滤内部提交标识和重放校验载荷。

治疗师预约查看：所有在职工作人员均可看预约基本信息并接待。治疗师自己的专业工作页面保留本人主服务／协作、登记服务照片、业绩及本人评估；共享预约权限不扩为他人照片、跨店财务或历史临床档案。取消仍保留原主治疗师范围，协作治疗师不会取得直接取消或前台取消审批权。客户评分与回访仅客户本人及老板可见。

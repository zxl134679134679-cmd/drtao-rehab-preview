# 涛博士运动康复 · 静态交互设计原型

用于查看与讨论界面和工作流程。使用麦岛店、崂山店的真实门店名称；客户、工作人员、预约、计划、收款和业绩均为虚构示例。

支持客户、康复师、老板、前台和店长角色体验；可模拟到店、服务照片留底、消课、收款、退款记录、平台待结算与到账。本页面不会执行真实付款或退款。

页面数据仅保存在当前访客页面内存中，刷新恢复初始示例。未接入微信登录、真实客户档案、持久数据库或平台自动对账。

老板快捷入口：`?preview=boss`；前台快捷入口：`?preview=frontdesk`。这些仅选择演示角色，正式系统必须使用真实身份和服务端权限。

客户分享入口：`?preview=customer`。直接展示客户页面，隐藏角色切换与管理演示控件，保留计划、次数、预约、服务记录及评价体验，并持续标注示例资料。原链接及老板、前台入口继续可用。此入口是展示模式，不代表正式账号权限。

新增客户评估与前台工作考核：前台在授权门店代录评估项目、指标和说明，由指定评估康复师、客户负责人或老板确认后供客户查看；历史记录及有原因的撤销保留。评估记录独立于消课、收款和康复计划。实际评估时间按上海时区校验，尚未发生的时间不能登记或确认。老板可从前台人员的“工作记录”查看经办数据并填写考核结论、改进事项和日期，前台只查看自己的考核。所有记录仍仅保存在当前页面内存中。

客户服务评价：除客户本人外，评分、文字反馈与回访处理记录仅老板可查看；康复师和前台的界面、服务明细、工作待办及演示导出不显示这些记录。客户填写前和查看已提交评价时均展示权限提示，申请联系交由老板处理。此处仅演示角色规则，正式版仍须以服务器鉴权和隔离的数据响应实现相同权限。

同行预约：前台、老板或有客户权限的康复师可一次安排2至20位已建档客户，在同一门店、同一日期整点或半点到店，每人各自选择不同且有资格服务该客户的康复师。整组统一校验，任一成员冲突或越权均不保存，相同请求重试只返回原组。每人一条独立预约（仅共用groupId，不携带其他人的档案），分别到店、改约、取消、消课与评价；预约不改变套餐次数或收款。朋友未建档时先由老板、店长、前台或康复师按建档权限建立基本档案，再由有预约权限的工作人员安排同行预约。

店长入口：`?preview=manager`（麦岛店）或 `?preview=manager&store=b`（崂山店）。店长账号绑定一家门店，首页查看本店今日实收、预约、完成服务及待处理事项，并可查看本店客户、服务照片留底、评估、收退款与平台结算、人员业绩和前台考核。所有明细和导出按记录实际门店过滤；同一客户的两店套餐分别使用，店长查看本店套餐次数，其他门店的工作记录不展示。无明确门店的历史待办归客户所属门店。客户私人评价及评价回访任务继续仅客户本人和老板可见，不给店长开放。店长可为本店新客户建立基本档案、记录客户自述及服务前确认；专业复核由客户负责康复师完成。收款、预约和消课仍由对应工作人员办理，退款和更正由老板处理。老板在“门店与人员”新增或停用店长账号；新门店可绑定新的店长。以上仅演示权限，正式上线须由服务端验证真实账号。

客户预约首页：预约为主要入口，三步选择门店、期望日期时间、核对并提交申请。时间以半小时选择，不代表实时空位。客户看本店剩余次数，不展示金额或充值余额。评分不预选，除本人外仅老板可见。

预约申请单独留存；申请不扣次、不记收款。授权门店前台、客户负责人或老板核对排班后，调用同一预约流程确认，重新检查权限与既有60分钟预约冲突。申请去重及提交标识别名防止重复申请；失败保留填写内容。已处理的申请展示提交时历史，当前安排以真实预约记录为准。已接入页面内已确认排班校验：未排班、休息、非排班门店和完整60分钟超出上下班时间均不能安排；正式系统的排班同步和通知发送仍待服务端接入。

本店套餐：同一客户可以持有麦岛店和崂山店两份套餐，各自保留成交金额、总次数、期初使用及消课。套餐只能在所属店使用；消课明确选择本店有余套餐，撤销恢复原套餐槽位。老板可办理新本店套餐，不自动生成收款或消费业绩。新纸质档案和续费绑定门店。纯模型保留未绑定旧套餐的兼容路径，须核对所属店后用于实际迁移，不能据此将新卡当作两店通用。

前台新客户接待：首页“接待新客户”、客户列表保留同一入口。先按手机号检查原档案，再记录姓名、年龄、客户自述主要问题、接待门店及本店负责康复师。外店已有档案只提示请老板核对权限，不暴露无权限身份；同一手机号禁止重复建档，连续提交幂等。建档后显示明确结果并可直接为这位客户预约；老客户可按姓名/手机号查找、查看基本接待资料。新档案未办套餐、不收款、不消课、不产生评估结论或业绩；老板后续办理首张本店套餐。前台只在授权且启用的门店建档，不修改原档案负责人，不办卡、改次数或处理退款。全部仍是虚构页面内存演示，真实资料需正式服务端接入。


四种工作角色建档：老板可选全部启用门店，店长可建本店档案，前台可建授权启用门店档案，康复师只在本人门店建档并由本人负责。工作台和客户列表提供“新客户建档”；建档后可填写初访接待表。店长成功结果提示交给前台或负责康复师安排评估，不开放预约、收款、消课或专业复核操作。基础档案保存年龄和客户自述问题，不产生费用、套餐、服务或业绩。

纸质流程数字化：前台 → 评估 → 初访与评估 → 填写本次接待表。姓名、电话和负责人从客户档案带入；问题、年龄、目标在表内填写，部位、持续时间、活动影响、客户自述疼痛和背景信息按需记录。十项服务前问题逐项选“是／否／不清楚”，默认不选；全部填否仍待负责人复核，未成年须补充监护人。保存后由当前在职负责康复师复核并记录具体下一步。旧回答、录入人和日期保留；下一次情况改变可以新增记录，历史不能替代本次确认。老板／店长工作台集中显示本权限范围的待复核数量、主要问题、需要核对事项、负责人和下一步，完整详情按需打开。专业评估、出席、套餐和收款沿用原有模块，接待表不会重复登记或自动扣次。客户端及客户导出不显示内部接待表。预览均为虚构，真实健康资料不能录入公开演示。


康复师排班：老板、店长、前台和康复师工作端增加“排班”入口，按日期显示09:00–19:00、休息或未排班。预览默认展示今日起14天虚构班次（许映今日休息），其他日期须先由老板或店长确认；加载真实状态不自动补排班。前台在授权门店只提交调整申请，原排班保持不变。老板或本店店长一人批准即可；两者直接保存也视为本人确认，不用重复审批。调整须填写原因，支持整点及半点，历史只读，版本变化要求重新核对。会影响现有预约时必须先处理预约，不能直接改成休息或缩短到无法完成服务。

每次生效变更原子生成老板系统内通知，保存修改人／申请人、批准人、门店、康复师、日期、改前改后、原因和生效时间；标为已读后仍留底。微信通知意向保留为 pending_integration，预览明确“待正式接入，当前未发送”，不会调用微信或发送真实消息。前台无直接改排班权限，店长仅本店，康复师只读本人，客户不显示内部排班表或通知。导出沿用同样权限，过滤内部提交标识。

单人预约、同行预约、客户申请和改约均核对已确认班次，界面显示当天排班并禁用班外及已有预约占用时段，每次服务按60分钟预留。客户端可选择该店有客户服务权限的康复师。确认申请时再次检查排班；申请不占用时段、不收款、不扣次数。服务更正仍恢复原套餐次数和业绩，如果原预约已不符合当前排班，则保留为“待重新安排”，不会阻止合法更正或自动取消客户预约。
